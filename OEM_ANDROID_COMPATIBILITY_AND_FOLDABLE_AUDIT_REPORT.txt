3. REAL OEM BEHAVIOUR & SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------

A. Edge-to-Edge & System Bars (Android 15 Mandate):
- Android 15 enforces edge-to-edge window drawing by default.
- BALKAVACH handles this cleanly:
  * Uses `SystemUiMode.edgeToEdge` when returning from fullscreen video playback.
  * Wraps screen bodies in `SafeArea` or utilizes `MediaQuery.paddingOf(context)`
    for custom headers.
  * System bars maintain WCAG-compliant contrast across light/dark backgrounds.

B. Xiaomi / Redmi / POCO HyperOS & MIUI Specifics:
- Physical Hardware Tested: Xiaomi Redmi/POCO `22041219I` running HyperOS V816 (Android 14).
- Graphics Backend: Verified running Google Impeller with Vulkan:
  `[IMPORTANT:flutter/shell/platform/android/android_context_vk_impeller.cc(62)] Using the Impeller rendering backend (Vulkan)`.
  No rendering artifacts or shader compilation stutters observed.
- Package Installation Quirks:
  HyperOS "Dual Apps" creates an internal secondary profile (`UserInfo{999:XSpace}`).
  Standard uninstalls via ADB or user drag-and-drop remove the app from User 0
  only, leaving stale signatures in User 999 which triggers:
  `Failure [INSTALL_FAILED_UPDATE_INCOMPATIBLE: Existing package signatures do not match newer version]`.
  Resolution: Clear Dual Apps cache in Settings > Apps > Dual apps > Settings >
  "Delete Dual Apps' accounts", or deploy via `adb install -r --user 0`.
- Background Power Management:
  MIUI/HyperOS aggressive battery optimizer can suspend background push channels.
  The app correctly registers `balkavach_missions` notification channels with
  high priority and default sound to ensure delivery.

C. Samsung One UI Specifics (One UI 5.1 / 6.0 / 6.1):
- Navigation Bar: Samsung allows users to select either 3-button navigation
  (bottom inset: 48-56 dp) or gesture navigation (bottom inset: 20-24 dp, or
  0 dp when "Gesture hint" is disabled).
  The app adapts dynamically via `MediaQuery.paddingOf(context).bottom`.
- Samsung DeX & Pop-up View:
  When launched in floating window / pop-up view (e.g. 340 x 500 dp), the app
  functions seamlessly without assuming full-screen dimensions.
- Configuration Changes:
  `android:configChanges` in `AndroidManifest.xml` includes:
  `"orientation|keyboardHidden|keyboard|screenSize|smallestScreenSize|locale|layoutDirection|fontScale|screenLayout|density|uiMode"`.
  This prevents unnecessary Activity destruction and re-creation when entering
  DeX or resizing pop-up windows.

D. Vivo / iQOO Funtouch OS & Motorola My UX (Curved Displays):
- Curved-edge screens introduce horizontal system padding (left and right insets
  typically 12-16 dp) to prevent accidental palm triggers.
- Audit revealed that relying solely on `MediaQuery.sizeOf(context).width`
  caused horizontal overflows in tight horizontal rows.
  Fix applied to account for `padding.horizontal` (see Section 5).

E. Google Pixel & Stock Android (Predictive Back & Gestures):
- Navigation utilizes GoRouter and modern Flutter pop handling without any
  deprecated `WillPopScope` widgets.
- Seamlessly supports Android 14+ predictive back swipe gestures without
  abruptly killing child tasks or unsubmitted forms.

F. Virtual Keyboard Resizing (adjustResize):
- `android:windowSoftInputMode="adjustResize"` is properly configured in
  `AndroidManifest.xml`.
- When virtual keyboards open (Gboard, Samsung Keyboard, Celia, SwiftKey),
  `viewInsets.bottom` adjusts the visible viewport.
- Forms (`ParentAuthScreen`, `CreateChildScreen`, `CreateMissionScreen`,
  `MissionSubmitScreen`) verify that the active `EditableText` remains fully
  visible above a 300 dp keyboard inset.

G. Fullscreen Video & Orientation Locking:

5. DEFECTS DISCOVERED & RESOLUTIONS APPLIED
--------------------------------------------------------------------------------

Defect 1: AppBar Action RenderFlex Overflow on Curved Displays / Side Insets
- Severity: Medium (Visual UI Bug / Layout Overflow)
- Affected Devices: Motorola Edge series, Vivo V-series, and foldables in
  split-screen with lateral safe area padding (left: 16 dp, right: 16 dp).
- Symptoms:
  `RenderFlex overflowed by 6 pixels on the right` in `ChildShell` AppBar
  trailing slot when tested on a 393 x 852 dp curved screen profile.
- Root Cause:
  In `lib/features/missions/presentation/child_shell.dart`, `ParentGateButton`
  determined compact mode using:
    `final compact = MediaQuery.sizeOf(context).width / textScale < 380;`
  This evaluated total window width (393 dp) and failed to subtract side safe area
  padding (`padding.horizontal` = 32 dp). In reality, the usable width was only
  361 dp. Because `393 > 380`, `ParentGateButton` rendered the full-width
  `SecondaryButton` pill ("Parent Zone" + lock icon, ~140 dp wide). Combined with
  `PandaTalkButton` (48 dp), `NotificationBell` (48 dp), and `BrandTitle`, the
  trailing slot exceeded its available allocation (305 dp max) and overflowed.
- Resolution:
  Updated `lib/features/missions/presentation/child_shell.dart` to calculate
  the actual usable width inside safe insets:
  ```dart
  final textScale = MediaQuery.textScalerOf(context).scale(1);
  final padding = MediaQuery.paddingOf(context);
  final usableWidth = MediaQuery.sizeOf(context).width - padding.horizontal;
  final compact = usableWidth / textScale < 420;
  ```
  When usable width is constrained, `ParentGateButton` renders an
  `IconButton.filledTonal` (48 x 48 dp), ensuring the entire action group fits
  comfortably within safe margins without clipping.
- Verification:
  Retested across Motorola Edge / Vivo curved profile (393 x 852 with 16 dp insets)
  and all 11 OEM device profiles: All 321 tests PASSED with 0 errors.
